# CLAUDE.md

This file provides guidance to Claude Code (claude.ai/code) when working with code in this repository.

## Project

`terraforme` is a Rust CLI (Linux and Windows) that installs and manages three extensions for AI agents — [RTK](https://github.com/rtk-ai/rtk) (token savings), [AI Memory](https://github.com/akitaonrails/ai-memory) (cross-session memory) and [AI Jail](https://github.com/akitaonrails/ai-jail) (OS sandbox) — and launches the agent (currently only Claude Code) in modes that toggle the first two, optionally inside the jail. User-facing text, doc comments and code comments are in **Portuguese**; commit messages must be in **English**.

## Commands

```bash
cargo run -p terraforme-cli -- --help        # or: pnpm cli --help
cargo build -p terraforme-cli --release      # target/release/terraforme
./install.linux.sh                           # release build + install to ~/.local/bin (--update: git pull first; --dist; --uninstall)
.\install.windows.ps1                        # same on Windows (-Update/-Dist/-Uninstall), into %LOCALAPPDATA%\Programs\terraforme\bin + user PATH; UTF-8 BOM required (PowerShell 5.1)
terraforme upgrade                           # execs <repo>/install.linux.sh --update (install.windows.ps1 -Update on Windows) (repo = CARGO_MANIFEST_DIR/../.. at build time, or --repo / TERRAFORME_REPO); without that repo (release binary) it runs the install.sh / install.ps1 below from GitHub
curl -fsSL https://raw.githubusercontent.com/Augustowtg/terraforme/main/install.sh | sh    # release binaries, no Rust (Linux x86_64/aarch64 musl)
irm https://raw.githubusercontent.com/Augustowtg/terraforme/main/install.ps1 | iex         # same on Windows; install.ps1 must stay ASCII and wrapped in `& { }` (runs in the user's session: no `exit`)

cargo fmt --all
cargo clippy --workspace --all-targets -- -D warnings
cargo test --workspace
cargo test -p terraforme-core toml_round_trip   # single test (name filter)
```

`.github/workflows/ci.yml` runs fmt, clippy and tests on `ubuntu-latest` and `windows-latest` only on `v*` tags (new versions) and on manual `workflow_dispatch`, not on pushes or PRs, so run `cargo fmt`/`clippy`/`test` locally before opening a PR; it is the only place `#[cfg(windows)]` code is compiled (cross-checking for `x86_64-pc-windows-msvc` locally fails on `ring`, which needs `lib.exe`).

`release` has no LTO on purpose (fat LTO + 1 codegen unit left the last step, the `terraforme` binary, compiling on a single core for ~35s+, looking stuck at 181/182); the `dist` profile keeps that for distribution builds.

Toolchain is pinned to Rust 1.98.0 (edition 2024) via `rust-toolchain.toml`. Node/pnpm exist only for git hooks: `pnpm install` at the root enables Husky. `pre-commit` runs `cargo fmt --check` and `cargo clippy -D warnings`; `commit-msg` runs commitlint.

## Versioning and changelog

Every change that ships (feature, fix, behavior or build change — not pure refactors/docs) bumps `[workspace.package] version` in the root `Cargo.toml` (SemVer: minor for features, patch for fixes; both crates inherit it, refresh `Cargo.lock` with `cargo metadata` or a build) and adds a `## X.Y.Z - YYYY-MM-DD` section at the top of `CHANGELOG.md` (Portuguese, Keep a Changelog headings `Adicionado` / `Alterado` / `Corrigido` / `Removido`). Several changes in the same unreleased session go into the same new version. `install.linux.sh` prints the sections newer than the previously installed version after an update, so keep the `## <version>` heading format.

## Releases

`.github/workflows/release.yml` runs on a `v*` tag (must equal `v` + the `Cargo.toml` version): builds `terraforme` + `terraforme-mcp` with the `dist` profile for `x86_64-unknown-linux-musl`, `aarch64-unknown-linux-musl` (`musl-gcc` for `ring`) and `x86_64-pc-windows-msvc`, packs `terraforme-<target>.tar.gz`/`.zip` + `.sha256`, and creates the GitHub Release with that version's `CHANGELOG.md` section. `install.sh`/`install.ps1` download from it, so keep the asset names in sync.

## Commits

Conventional Commits, `<type>(<scope>): <subject>`. Rules in `commitlint.config.mjs`: allowed scopes are `core`, `cli`, `deps`, `ci`, `docs`, `config`, `release`; subject lower-case; header ≤ 100 chars; any non-ASCII character or common Portuguese word (e.g. `para`, `uma`, `cria`) is rejected.

## Architecture

Cargo workspace with three crates:

- **`crates/terraforme-core`** — all logic. The CLI is just a shell around it. The optional `clap` feature derives `clap::ValueEnum` on public enums (`Extension`, `Provider`, `Mode`) so the CLI can use them directly as arguments.
- **`crates/terraforme-cli`** — the `terraforme` binary: clap definitions and output formatting in `main.rs`, plus the TUI in `term.rs`.
- **`crates/terraforme-mcp`** — the shared `terraforme-mcp` daemon (axum, JSON-RPC over HTTP on `127.0.0.1`), started on demand by `terraforme cli` (`mcp::ensure_running`, lock file `<data dir>/terraforme/mcp.lock`) and shut down after the last client leaves. Every TUI registers itself (`/register` + heartbeat, with its control server address) and each agent instance (`/instances/register`, unregistered on `Agent` drop); the `hub` keeps instances from all spaces with a handle `<space or dir>/<agent>-<n>` and the message log. Tools: `list_instances`, `send_message` (delivered as `POST /message` to the target TUI's control server, which types it as a prompt via `Agent::queue`) and `spawn_subagent`. Each instance gets the server through `Adapter::mcp_args` (Claude: `--mcp-config` with `x-client-id`/`x-instance-id` headers; the two messaging tools are pre-allowed in the session `--settings`); with AI Jail, `jail::wrap` forwards the daemon port, so `run_term` starts the daemon before building the command. `[mcp] ui` enables the web UI at `/ui` (+ `/api/state`, `/api/send`), read from `config.toml` on every request and limited to local `Host`/`Origin`.

Core modules:

- `status` — `Component`/`State` (Installed / Conflict / NotInstalled) and PATH lookup + `--version` parsing helpers shared by the other modules. On Windows `find_in_path` follows `PATHEXT` (npm installs `.cmd` shims, e.g. `opencode.cmd`), and `std::process::Command` only completes `.exe`, so always spawn the returned full path (`status::command(bin)`), never a bare name.
- `platform` — the OS-specific process bits, the only place that uses `windows-sys`: `is_pid_alive` (`/proc` / `OpenProcess`), `ignore_ctrl_c` (on Windows there is no `exec`, so the parent waits on the child and must ignore the console's `Ctrl+C`) and `detach` (the MCP daemon gets no console on Windows and its own process group on Unix, so closing the launching terminal doesn't kill it).
- `extension` — install/update/delete for RTK and AI Memory using each project's official install scripts and their own subcommands (AI Jail has no install script: the release tarball is downloaded, checked against its `.sha256` and installed to `~/.local/bin`; update/delete refuse a copy outside it, e.g. Homebrew); external commands inherit the terminal. Also defines `Report`s (e.g. `rtk gain`, `ai-memory status`), which run the extension binary with `NO_COLOR` and return ANSI-stripped text.
- `usage` — Claude Code token consumption parsed from the transcripts in `~/.claude/projects/<cwd with non-alphanumerics → '-'>/<session>.jsonl` (respects `CLAUDE_CONFIG_DIR`). One response spans several lines, so entries are deduplicated by `message.id` + `requestId`. Subagent transcripts live in `<session>/subagents/agent-<id>.jsonl` (same `sessionId`, plus `agentId`; type/description in the sibling `.meta.json`). OpenCode delegates to `opencode stats --json` for project/day and global/day/week aggregates; its CLI does not expose a rolling five-hour window, current-session token totals or token breakdowns by subagent.
- `limits` — how much of the usage limits is left, standardized by terraforme: each agent's `Adapter::quota()` returns the plan limits in the `Quota` shape (Claude reads them from `api.anthropic.com/api/oauth/usage` — OAuth token read from `<claude dir>/.credentials.json`, never refreshed by us — and `limits` caches the result for 60s), and terraforme converts them to `Limit`s (percentage used, tokens, reset time), falling back to the config `[budget]` compared with transcript totals when the agent reports none. OpenCode exposes no plan limits and no five-hour window, so only the weekly budget entry is shown there.
- `config` — `Config { provider, mode, jail, budget, mcp, tui }` in `~/.config/terraforme/config.toml` (`%APPDATA%\terraforme` on Windows; respects `XDG_CONFIG_HOME`).
- `space` — named working directories (`Spaces`, a name → path `BTreeMap`) in `<config dir>/spaces.toml`, kept out of `config.toml` because `Config` is `Copy`. `terraforme space` picks one (list number or name) and `exec`s the user's shell there (`space::shell`, sets `TERRAFORME_SPACE`), since a process can't change its parent shell's cwd; `--path` prints the dir instead (prompts go to stderr) for a `cd "$(…)"` shell function. Per-space `Preferences` (optional `agent`/`mode`/`jail`/`account`) live outside the project in `~/.terraforme/<space name>/preferences.toml` (`space::root`, `TERRAFORME_HOME` overrides; space names can't contain `/`/`\`), set with `terraforme space <name> --agent/--mode/--jail/--account/--reset` and moved/removed with the space; `Spaces::load` migrates the legacy `<space dir>/.terraforme/preferences.toml`. `terraforme cli` uses the deepest saved space containing the cwd (`Preferences::find`) and resolves CLI flags → space preferences → project `.ai-jail` (jail only) → `config.toml`.
- `jail` — AI Jail integration: `DEFAULT_CONFIG` written to `~/.ai-jail` only when absent (on install and on a jailed launch), and `wrap()`, which turns the agent command into `ai-jail --no-save-config <maps> -- claude <args>`. Maps are passed per launch, never saved: each mode extension's plugin dir and binary (plus its symlink target dir) read-only, `~/.local/share/{rtk,ai-memory}` writable, and `--forward-port` for every `127.0.0.1:`/`localhost:` port found in the plugin's `hooks.json`/`.mcp.json` (AI Memory's local server). Requires ai-jail ≥ 2.9 (`--forward-port`) and `bwrap` on Linux. There is no AI Jail on Windows (`jail::is_supported`): a jail implied by a project `.ai-jail`, the config or a space is dropped with a notice, and only an explicit `--jail` errors. `ensure_project()` creates the project `.ai-jail` (`ai-jail --init <agent>`) when missing (never in `$HOME`, where it is the global file); it is called only explicitly via `terraforme extension ai-jail --project` — `terraforme cli` does **not** auto-create `.ai-jail` on launch. Never pass `--no-status-bar` on the CLI: ai-jail persists status-bar flags into `~/.ai-jail`.
- `agent` — `Provider` and `Mode` (`none` = no extension, `eco` = RTK, `high` = AI Memory, `hybrid` = both; AI Jail is never part of a mode — `Mode::uses` is false for it) plus `CliMode`, the start presets shown by `terraforme config --cli` (`eco` = RTK, `high` = AI Memory, `security` = AI Jail with no extensions, `custom` = the user picks the extensions; `preset()`/`of()` map them to `(mode, jail)`). Each agent is an `Adapter` trait object (`Provider::adapter()`, `None` = not implemented yet, e.g. Cursor): `bin`, `setup(mode)` (returns the agent args + per-extension plugin dirs), `session_args`/`picks_session`, `usage`, `quota` and `forget(ext)` (cleanup on extension delete). `agent::prepare()` is agent-agnostic: it checks the extensions, calls `setup`, appends passthrough args and wraps with `jail::wrap`, building the `std::process::Command` that `terraforme cli` runs in the TUI (or directly, with `exec`, under `--plain`). The TUI only talks to the agent through the adapter. To add an agent: a module in `agent/` implementing `Adapter`, a `Provider` variant, and the mapping in `Provider::adapter`. Claude Code lives in `agent/claude.rs` (it delegates to `usage::collect` and implements `quota()` with the plan's usage API, both Claude-specific).

### How modes work with Claude Code (`agent::claude`, `Claude::setup`)

This is the non-obvious part and it touches the user's global Claude config:

1. RTK/AI Memory hooks are **moved out** of `~/.claude/settings.json` (backup saved as `settings.json.terraforme-bak`) into per-extension local plugins at `~/.config/terraforme/plugins/terraforme-<ext>/hooks/hooks.json`. This happens on every launch, so if `rtk init -g` / `ai-memory setup` puts the hooks back in the global file, they are moved again. The global file is only rewritten after the plugins have been written.
2. For each extension used by the mode, `--plugin-dir <plugin>` is passed to `claude`.
3. The global AI Memory MCP server in `~/.claude.json` is **not modified**: it is blocked for the session via `--settings '{"deniedMcpServers":[{"serverName":"ai-memory"}]}'`, and the AI Memory plugin gets a copy of it in its `.mcp.json` (as server `memory`) when the mode uses it.
4. Extra args after `--` are passed through to `claude`.
5. With `jail` (`config.jail`, overridden by `--jail`/`--no-jail`), the whole command is wrapped by `jail::wrap`, and the TUI shows AI Jail reports in the Extensões tab.

As a result, running `claude` directly (without terraforme) gives a session without the RTK and AI Memory hooks.

### `terraforme cli` terminal (`term.rs`)

ratatui TUI with a tab bar on top: one agent tab (`claude` or `opencode`) whose sub-tabs, on a second line, are the agent instances (`claude 1`, `claude 2`…; `--instances/-n N` at launch, `Ctrl+Alt+N`/`F12` opens another, `Ctrl+Alt+W`/`Shift+F12`/`F24` kills the active one, `Ctrl+Alt+R` restarts it in place, max 9; a sub-tab disappears when its process exits and the TUI quits when the last one does), `Consumo` (sub-tabs Limites / Tokens / Subagentes, auto-refreshed every 5s for the focused instance — Claude uses transcripts and OAuth limits; OpenCode uses `opencode stats --json` for daily/project and weekly aggregates, without current-session or rolling five-hour detail — Antigravity uses the transcripts `agy` writes under `~/.gemini/antigravity-cli/brain` and the account limits it reports with `agy -p "/usage" --output-format json` (one weekly bucket per model group, with its reset time); the Limites view draws one Claude-style bar per limit: a green bar starting full at 100% that shrinks as tokens are consumed, with the total token limit and the reset time on the header; followed by the RTK `Report`s when the mode uses RTK, not auto-refreshed), `Extensões` only when there are non-RTK reports (AI Memory, AI Jail; `reports(tab, extensions)` splits them), and `Config` (always last: a `Form` over `FIELDS` that edits `config.toml` and saves on every change; `[tui] mouse`/`copy_on_select` apply live). Each instance runs in its own `portable-pty` pseudoterminal (on Windows a ConPTY created with `PSEUDOCONSOLE_INHERIT_CURSOR`: it sends `ESC[6n` at start and blocks the agent until `Agent::answer_cursor_queries` replies, and its reader never hits EOF when the child exits, so the event loop also polls `Agent::exited`), resized to the real screen before every draw (`App::fit`, not only on `Event::Resize`), rendered with `vt100` + `tui-term` (5000-line scrollback) and keeps running while another tab is open; non-agent tabs load their content on a background thread when selected. The kitty keyboard protocol (`DISAMBIGUATE_ESCAPE_CODES`) is pushed when `supports_keyboard_enhancement()` says so (`App::enhanced`), so `Ctrl+Shift`/`Ctrl+Alt` combos arrive distinct. Tabs are built with the **registry** design pattern: each tab is a single `TABS` entry (`TabSpec` — order in the menu, name, `Ctrl+Shift+F<n>` shortcut, own sub-tabs and `TabKind`: `Agent`/`Content`/`Form`), and menu, shortcuts, help and opening all read that list (`spec(tab)`), so no `match tab` is scattered around; adding a tab means adding an entry. Tabs: `Ctrl+Shift+F1` (Agent), `Ctrl+Shift+F2` (Consumo), `Ctrl+Shift+F3` (Extensões, only when the mode shows that tab) and `Ctrl+Shift+F4` (Config); all extra/duplicated tab shortcuts (`Shift+1/2`, `F1/F2`, `Ctrl+Shift+1..9`, `Shift+F1..F9`, `Ctrl+Shift+Tab`, `Shift+Tab`) are disabled so `Shift+Tab`, digits and function keys reach the agent. Sub-tabs, the same in every tab (`App::pick`/`App::cycle`/`App::open_sub`): `Ctrl+Alt+Tab` (Shift = back; legacy arrives as `Alt+Tab`) and `Ctrl+PgUp/PgDn` cycle, `Ctrl+Alt+1`–`9` / `Alt+1`–`9` jump (`sub_tab_number`, digits only — symbols would catch AltGr on Windows), and in the agent tab a number past the last instance opens a new one. TUI commands are `Ctrl+Alt+letter` (`n w r c s k`; `k` = shortcut list in a `Popup`), chosen to dodge Linux desktop bindings (`Ctrl+Alt+T/L/D/Del/F*/arrows`) and letters whose legacy control byte collides with another key (`Ctrl+Alt+M` = `Alt+Enter`, `H` = Backspace, `I` = Tab, `J` = LF). `Ctrl+←→` is not bound (it reaches the agent for word movement). Every sub-tab bar is drawn by `sub_tab_spans` (`⌃⌥N label`, or `⌥N` without the protocol), `F10` quits. Key events are translated to xterm byte sequences in `key_bytes` (which respects application-cursor mode). Mouse capture is on by default (`[tui] mouse`; `Ctrl+Alt+S` toggles it at runtime) so the wheel scrolls (otherwise the terminal turns it into arrows, which reach the agent as prompt history): in the agent tab it is forwarded as a wheel event (`wheel_bytes`, the agent's encoding) when the agent enabled mouse reporting, sent as arrows on its alternate screen, and otherwise scrolls the `vt100` history; in the other tabs and popups it scrolls the content. Left-drag in the agent tab makes a `Selection` (screen cells, highlighted over the rendered buffer, read with `contents_between`) that is copied on release (`[tui] copy_on_select`) by `clipboard()`: OSC 52 plus, on Linux, `wl-copy`/`xclip`/`xsel` (VTE ignores OSC 52); `Ctrl+Alt+C` copies the selection, the visible screen or the open tab's text. Short feedback goes to `App::status` (bottom-right, `STATUS_TTL`). Notices/warnings from `prepare()` are shown in an initial popup, because the alternate screen would hide anything printed before it.
